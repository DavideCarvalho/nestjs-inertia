---
title: Auth Redirect Guard (recipe)
description: How to write an NestJS guard that sends 302 for browsers and 409 for Inertia XHR.
---

The Inertia protocol specifies that when an authenticated route is accessed without a valid session, a server should reply with `302 Location: /signin?return_to=…` for plain browser visits and `409 X-Inertia-Location: …` for Inertia XHR requests (so the client-side router can navigate without a full reload).

The library does **not** ship a built-in guard for this because the auth UX — which URL is the sign-in page, what constitutes an "authenticated" request, allow-list rules — belongs to the application.

## Recipe

```ts
import { type CanActivate, type ExecutionContext, Injectable } from '@nestjs/common';

@Injectable()
export class AuthRedirectGuard implements CanActivate {
  private readonly signInUrl = '/signin';

  canActivate(ctx: ExecutionContext): boolean {
    const req = ctx.switchToHttp().getRequest<{
      user?: unknown;
      url?: string;
      originalUrl?: string;
      headers: Record<string, string | undefined>;
    }>();
    const res = ctx.switchToHttp().getResponse();

    // Replace with your own session / JWT check
    if (req.user) return true;

    const rawUrl = req.originalUrl ?? req.url ?? '/';
    const path = new URL(rawUrl, 'http://localhost').pathname;
    const isEcho = path === this.signInUrl;
    const target = isEcho
      ? this.signInUrl
      : `${this.signInUrl}?return_to=${encodeURIComponent(path)}`;

    if (req.headers['x-inertia']) {
      // Inertia XHR — tell the client-side router to hard-navigate
      res.status(409);
      res.setHeader('X-Inertia-Location', target);
      res.end();
    } else {
      // Plain browser visit
      res.redirect(302, target);
    }
    return false;
  }
}
```

Apply it per-route or globally:

```ts
@Get('/dashboard')
@UseGuards(AuthRedirectGuard)
@Inertia('Dashboard')
show() { return {}; }
```
