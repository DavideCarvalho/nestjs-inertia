---
title: Migrating from Inertia v2 to v3
description: Step-by-step guide for upgrading from nestjs-inertia v0.8.x (Inertia v2) to v0.9.x (Inertia v3).
---

`@dudousxd/nestjs-inertia@0.9.0-alpha.0` aligns with the **Inertia.js v3** wire protocol. This guide covers the breaking changes and the steps required to upgrade.

> If you want to stay on Inertia v2, pin `@dudousxd/nestjs-inertia@0.8.x` and do not upgrade.

## 1. Upgrade client adapter packages

### React

```bash
pnpm add @inertiajs/react@^3.0.0 react@^19.0.0 react-dom@^19.0.0
pnpm add -D @types/react@^19.0.0 @types/react-dom@^19.0.0
```

### Vue 3

```bash
pnpm add @inertiajs/vue3@^3.0.0
# Vue 3 itself is unchanged — ^3.5.0 is fine
```

### Svelte

```bash
pnpm add @inertiajs/svelte@^3.0.0 svelte@^5.0.0
```

## 2. Update the Vite config (Svelte only)

`@inertiajs/svelte` v3 exports only the `svelte` condition. Add `resolve.conditions` and load the Svelte Vite plugin manually:

```ts
// vite.config.ts
import nestInertia from '@dudousxd/nestjs-inertia-vite/plugin';
import { svelte } from '@sveltejs/vite-plugin-svelte';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [
    nestInertia({ svelte: true, skipFrameworkPlugin: true }),
    svelte(),
  ],
  resolve: {
    conditions: ['svelte', 'browser', 'module', 'import', 'default'],
  },
});
```

React and Vue do not require this change.

## 3. HTML shell — no action needed

The `@inertia` template directive in your `inertia/index.html` **automatically** uses the v3 format:

```html
<!-- v2 output (deprecated) -->
<div id="app" data-page="{{page}}"></div>

<!-- v3 output (current) -->
<div id="app"></div>
<script id="inertia-page" type="application/json">{{page}}</script>
```

If you hand-wrote the `data-page` div instead of using `@inertia`, update it to match the v3 format above.

## 4. Replace `Inertia.lazy()` with `Inertia.optional()`

`Inertia.lazy()` is deprecated in v3. The alias is kept for backwards compatibility but will be removed before v1.0.

```ts
// Before
@Inertia('Dashboard')
index() {
  return {
    expensive: Inertia.lazy(() => heavyFetch()),
  };
}

// After
@Inertia('Dashboard')
index() {
  return {
    expensive: Inertia.optional(() => heavyFetch()),
  };
}
```

## 5. `clearHistory` / `encryptHistory` — falsy values omitted

In v3, the `clearHistory` and `encryptHistory` page properties are **not emitted** when their value is `false` or `undefined`. They are only included in the page object when explicitly `true`. This matches the v3 protocol spec. No action required unless you relied on the explicit `false` value being present on the client.

## 6. Dot-notation partial reloads (new feature)

You can now target nested props in `only` / `except` partial-reload arrays using dot-notation:

```ts
// Target a nested prop
res.inertia.render('Profile', data, { only: ['user.profile'] });
```

This is additive — flat prop names continue to work as before.

## Packages affected

| Package | Old version | New version | Breaking? |
|---------|------------|-------------|-----------|

| `@dudousxd/nestjs-inertia-codegen` | 0.8.x | 0.9.x | No |
| `@dudousxd/nestjs-inertia-testing` | 0.8.x | 0.9.x | No |
