### Architecture decisions
- `defineContract` + `@ApplyContract` is the **advanced** path (explicit Zod); NestJS decorators are the **zero-config** path
- Route names: `ClassName.methodName` → strip Controller suffix, lowercase first letter → `crew.getCrew`
- `@As` decorator overrides class/method portions of route name
- Every route gets a contract entry (even without @Body/@Query annotations) — `ReturnType<import(...)>` handles response
- Changeset config uses `fixed` (all 5 packages share same version)

## Features to Implement

### Feature 1: Type-safe `@Inertia("PageName")`

**Goal:** `@Inertia("Chatt/Index")` errors at compile time if page doesn't exist.

**Approach:**
1. `emit-pages.ts` already discovers pages and writes `pages.d.ts`. Extend it to emit a union type:
   ```ts
   export type InertiaPageName = 'Home' | 'Crew' | 'Chat/Index' | 'Chat/Thread' | ...;
   ```
2. Add module augmentation in the generated output:
   ```ts
   declare module '@dudousxd/nestjs-inertia' {
     interface InertiaPages {
       'Home': true;
       'Crew': true;
       'Chat/Index': true;
     }
   }
   ```
3. Update `packages/core/src/markers.ts` — the `@Inertia()` decorator should accept `keyof InertiaPages` instead of `string`.
4. Update `packages/core/src/types/registry.ts` — add `InertiaPages` interface (empty by default, augmented by codegen).

**Test:** Create a fixture with `@Inertia('NonExistent')` and verify TypeScript errors.

### Feature 2: Props E2E type safety

**Goal:** If `@Inertia("Crew")` returns `{ users: User[] }` but `Crew.tsx` exports `ComponentProps = { crew: CrewMember[] }`, TypeScript errors.

**Approach:**
1. `emit-pages.ts` already extracts `ComponentProps` from each page. Extend the pages map to include prop types:
   ```ts
   interface InertiaPages {
     'Home': { greeting: string };
     'Crew': { crew: CrewMember[] };
   }
   ```
2. The `@Inertia('Crew')` decorator's return type should be constrained to `InertiaPages['Crew']`.
3. In `markers.ts`, make the decorator generic:
   ```ts
   export function Inertia<K extends keyof InertiaPages>(page: K): MethodDecorator
   ```
   The controller method's return type should be assignable to `InertiaPages[K]`.
4. For `req.inertia.render(page, props)`, type the `render` method similarly.

**Challenge:** The return type constraint needs to work with NestJS's decorator system. May need a custom interceptor that checks types at compile time but is a no-op at runtime.

**Test:** Navy's `ShowCrewController` with `@Inertia('Crew')` — verify props match the page's ComponentProps.

### Feature 3: `useInfiniteQuery` support in codegen

**Goal:** Automatically generate `infiniteQueryOptions()` for paginated endpoints.

**Approach:**
1. In `contracts-fast.ts`, detect pagination patterns in the response type:
   - `{ data: T[], meta: { page: number, lastPage: number } }` (common NestJS pattern)
   - Or controllers decorated with a custom `@Paginated()` decorator
2. In `emit-api.ts`, when pagination is detected, generate both:
   ```ts
   getCrew: {
     queryOptions: (...) => ...,
     infiniteQueryOptions: (params) => ({
       queryKey: [...],
       queryFn: ({ pageParam }) => fetcher.get(..., { query: { ...params, page: pageParam } }),
       initialPageParam: 1,
       getNextPageParam: (lastPage) => lastPage.meta.page < lastPage.meta.lastPage ? lastPage.meta.page + 1 : undefined,
     }),
   }
   ```
3. Import `infiniteQueryOptions` from `@tanstack/react-query` in the generated file.

**Test:** Navy's `GetImpersonationConfigController` returns paginated data — verify `infiniteQueryOptions()` is generated and replaces the manual `impersonationConfigQuery.ts`.

### Feature 4: URL params in `mutationOptions()`

**Goal:** `api.crew.updateCrew.mutationOptions()` handles `:id` without manual `fetcher.patch(route(...))`.

**Approach:**
1. The codegen already knows which routes have path params (from `extractParams`).
2. For routes with params, generate `mutationOptions` that accepts `{ params, body }`:
   ```ts
   updateCrew: {
     mutationOptions: () => _mutationOptions({
       mutationFn: ({ params, body }: { params: { id: string }, body: ApiRouter["crew"]["updateCrew"]["body"] }) =>
         fetcher.patch<...>(route("crew.updateCrew", params), { body }),
     }),
   }
   ```
3. Same for `queryOptions` on GET routes with params:
   ```ts
   getVesselTrail: {
     queryOptions: (params: { id: string }, query?: ...) => _queryOptions({
       queryKey: ["fleet.getVesselTrail", params, query],
       queryFn: () => fetcher.get<...>(route("fleet.getVesselTrail", params), { query }),
     }),
   }
   ```
4. Generate a `Params` type in `ApiRouter` for each route:
   ```ts
   updateCrew: { method: "PATCH"; url: ".../:id"; params: { id: string }; body: ...; response: ... };
   ```

**Test:** Navy's crew CRUD — verify `api.crew.updateCrew.mutationOptions()` works with `{ params: { id }, body: { name } }`.

### Feature 5: CLI `nestjs-inertia doctor`

**Goal:** One command to diagnose setup issues.

**Approach:**
1. Add `doctor.ts` in `packages/codegen/src/cli/`.
2. Register as a subcommand in the CLI entry.
3. Checks:
   - `tsconfig.json` exists and has `paths` with `@/*`
   - `tsconfig.inertia.json` (if exists) has `~/*` and `~codegen/*` paths
   - `vite.config.ts` has `resolve.alias` with `@`, `~`, `~codegen`
   - `nestjs-inertia.config.ts` exists and is valid
   - `.nestjs-inertia/` directory exists and has `api.ts`, `routes.ts`, `pages.d.ts`
   - `@inertiajs/react` (or vue/svelte) is v3+
   - All 5 `@dudousxd/nestjs-inertia-*` packages are same version
   - `package.json` has `build:client` and `build:ssr` scripts
   - `.gitignore` includes `.nestjs-inertia/`
4. Pretty output with checkmarks/crosses and fix suggestions.

### Feature 6: HMR for routes

**Goal:** When watcher regenerates `routes.ts`/`api.ts`, Vite HMR updates the frontend without full reload.

**Approach:**
1. In `packages/vite/src/plugin/plugin.ts`, watch the `.nestjs-inertia/` directory.
2. When files change, use Vite's `server.ws.send({ type: 'full-reload' })` or better, `server.moduleGraph.invalidateModule()` for the specific modules that import from `~codegen/*`.
3. Alternatively, add `import.meta.hot.accept()` to the generated `api.ts` and `routes.ts` so they self-accept HMR updates.
4. The watcher in `packages/codegen/src/watch/watcher.ts` could emit a signal (e.g., touch a sentinel file) that the Vite plugin watches.
